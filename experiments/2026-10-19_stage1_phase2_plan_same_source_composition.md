# Stage-1 same-source Phase-2 plan candidate composition

## Purpose

Test whether the Stage-1 adapter output and its matching QA inputs can flow
through a baseline-v3 candidate into `create_qta_phase2_plan_manifest_candidate`
without combining unrelated baseline and source-pin fixtures. Verify the
ordered token, batch, source, Phase-1 receipt, baseline row, and P/Q bindings,
and check fail-closed behavior after source or baseline mutations.

## Setup

- Added `scripts/test_qta_stage1_phase2_plan_same_source_composition.py`.
- Reuses the same-source CPU composition from
  `scripts/test_qta_stage1_baseline_prediction_link_composition.py`. That
  composition calls the actual synthetic `QtaStage1SourcePinAdapterTests.invoke()`
  on the same Stage-1 fixture and QA input bytes, then creates baseline-v3 rows
  from those pins and QA rows.
- Builds the preflight's review/source rows from the exact Stage-1 review
  intervals and source pins and baseline's ordered tokens and score bindings.
  Clock calibration is an explicit synthetic identity mapping; five temporal
  groups and the evidence/control group layout are scaffolding for structural
  plan validation, not a measured processor layout.
- `processor_batch_sha256` is a synthetic per-token placeholder generated by
  the preceding baseline composition and reused consistently in the baseline,
  synthetic preflight rows, Phase-1 receipt bindings, and Phase-2 plan. It is
  not a digest of an actual typed processor batch and provides no processor
  provenance.
- Creates and verifies a local synthetic Phase-1 signed receipt using temporary
  test keys. Its `record_token` is SHA-256 of the Stage-1 review token; its
  batch value is the corresponding synthetic placeholder. The Phase-2 test
  exercises candidate creation, not the full
  `verify_qta_phase2_plan_candidate` path.
- No model, GPU, protected dataset, actual video, or human review is used.
  Baseline option log probabilities remain synthetic placeholders.

## Verified results

- Dedicated test module: **2/2 passed**. Positive path produced a three-row
  `qta_phase2_nine_branch_plan_manifest_v2` candidate; its stored Phase-1
  receipt and baseline manifest digests matched the exact input bytes. Each
  row's hashed token, synthetic batch placeholder, baseline row digest, P/Q
  indices, and score-binding digest matched the same ordered Stage-1/baseline
  row.
- The composed synthetic preflight accepted **3/3** rows. The plan candidate
  retained `execution_authorization=not_granted`, `model_load_permitted=false`,
  `scoring_authorized=false`, and `authorized_forwards=0`.
- Negative checks rejected Stage-1 `reviewed_intervals_sha256`,
  `source_video_sha256`, and `claim_sha256` mutations with
  `phase2_plan_stage1_source_pin_mismatch`; a baseline claim mutation with
  `baseline_pq_score_binding_source_mismatch`; reordered baseline rows with
  `phase2_plan_record_or_batch_mismatch`; and a Phase-1 batch substitution with
  `phase2_plan_binding_mismatch`.
- Focused regression suite (`test_qta_stage1_phase2_plan_same_source_composition`
  plus `test_qta_phase_freeze_receipts`): **42/42 passed**. `py_compile` and
  scoped `git diff --check` also passed.

## Interpretation and limitations

This confirms a same-source structural join through the Phase-2 plan candidate
entrypoint for the stated synthetic rows. The Phase-1 receipt is a temporary
test signature, not an independently trusted or externally pinned ceremony.
The processor batch digest is reused synthetic text-derived data, and the
clock/temporal groups are fabricated scaffolding. Therefore these checks do not
verify real preprocessing, frame timing, model execution, scorer output,
reviewer identity, semantic review, or authorization.

The full `verify_qta_phase2_plan_candidate` verifier was not run in this test;
in particular, its baseline-to-signed-runtime and attention-capture bindings
remain untested by this composition. Candidate creation does not establish that
these runtime artifacts match. No faithfulness score or effect was measured,
so there is no effect estimate, interval, or inferential test to report.

Direct faithfulness status is unchanged: **0/3** formal claim reviews,
**0/15** player-clock/decoder-frame correspondences, **0/3** Stage-2
prediction-link reviews, **0/3** direct scores, and no measured real-data
faithfulness effect or uncertainty interval.

## Next action

If extending this synthetic handoff, separately bind the full Phase-2 verifier's
runtime and capture artifacts to the same baseline candidate bytes. Keep that
structural work distinct from real-data claims; direct scoring still requires
the independent review/provenance gates and an appropriate frozen experiment.
