# Prespecified plan: WP1-TVB, evidence-interval pathway knockout on TVBench Action Sequence (written 2026-10-31, before any WP1-TVB run)

Why: the user requires the experiments in the deck to share one benchmark (TVBench). The earlier evidence-interval experiment (WP1) used NExT-GQA because it has annotated answer intervals. Of the four locally available TVBench tasks only Action Sequence carries a per-question time window (`start`,`end`; 437 questions, 2 options, window mean 15.6 s); the other three have no time annotation, so this experiment is Action Sequence only. The official code uses that window to crop the video; here the FULL video is given and the window is the annotated interval (evidence), as in WP1.

Design (fixed now; label-free, uses TVBench's own annotation): Qwen2.5-VL-7B-Instruct 4-bit/BF16, sdpa explicit-mask hooks, 32 frames (16 temporal groups), fp32 readout over labels A/B. Cohort: Action Sequence, one question per video, hash-ranked (`tvb-ev-v1`), requested N=200; videos whose window covers more than 8 of 16 groups (no equal-count disjoint sham possible) or none are recorded as excluded (expected ~40%, i.e. ~115 eligible). Per eligible video: baseline; V2T and V2L knockouts, band layers 6-20 and all layers, of (a) the window's groups and (b) an equal-count disjoint hash sham, plus a whole-video V2T positive control (as WP1). Margin = logP(gold) - logP(other option). Also recorded: %p change of the predicted option (the base paper's metric).
Primary (one analysis, video = unit): P1 = V2T band, mean per-video (evidence minus sham) margin change; supported iff t, sign-flip, Wilcoxon p < 0.05 and mean <= -0.3 nat (delta_min carried over from WP1; NOT re-derived for the 2-option TVBench margin, flagged as a limitation) ; P2 = V2L band equivalence at +/-0.3 nat (TOST); Holm over P1/P2; positive control: whole-video V2T mean %p <= -20% on baseline-correct videos, else nulls are uninformative. Analysis script: scripts/analyze_evidence_pathway_knockout.py (unchanged). Secondary (descriptive): %p by arm.
Limits: window covers ~half of the video on average (eligible subset: windows <= half), so evidence and sham are both large fractions of the keys; windows are TVBench's annotation of the question's relevant segment (not calibrated to decoded PTS); one model, one task; two-option margin.
Workload: ~115 x 11 forwards, ~1-1.5 h. Runner scripts/run_tvbench_evidence_knockout.py (smoke n=3 first).
