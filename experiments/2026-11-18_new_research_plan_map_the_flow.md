## 0. 進め方 (2026-11-18 ユーザー指示: まず走らせてみて、基準を修正する)
基準の数値 (δ_min、FDR 水準、安定性閾値、効果の保持率、窓幅 k、部分集合の密度 p など) は、仮の値として置く。dev 段階は探索的であり、dev の結果を見て基準を調整してよい。ただし次を守る:
1. 動画を dev / test に、結果を見る前に分割し (seed 固定、動画単位、層別にタスクを均等)、test は凍結基準が決まるまで開かない。
2. dev での基準の調整は、すべて「調整履歴」(日時・変更前後・理由・見た結果) として本ファイルに追記する。
3. dev で決めた基準を「凍結」し (コミットで時刻を残す)、その後の test 評価は、凍結基準で1回だけ行う。これが確認的な一次解析。凍結後に基準を変えたら、test は探索的に格下げする。
4. dev で見えた効果を、そのまま確認的な結果として報告しない。
データ分割: TVBench 5 タスク 1322 問を、動画単位で dev 50% / test 50%。Moving Direction は dev でベースライン精度を確認し、偶然水準 (25%付近) なら解析から外す (事前に決めたルール)。

## 1. 論文の測り方の問題 (本計画で直す点)
1. 指標が「正解確率の相対変化」で、元の確率が小さいと不安定、飽和し、外れ値に弱い。
2. 「ベースラインで正解した問題だけ」を使う。これを条件にすると、元の確率が高い側に偏るため、何を遮断しても平均で下がる (平均への回帰)。対照の遮断がない。
3. 有効層は Action Antonym だけから、5層刻み・閾値 -5% (根拠の記述なし) で決められ、他タスクでの確認がない。
4. 操作が層の範囲だけで、答えが動画の端にある課題 (Object Count、Action Sequence は「最初/最後」を問う) で、どのフレームが効いたか分からない。
5. 区間・検定・多重性補正がない。

## 2. 窓幅 k の方針と妥当性
### 想定
- 主解析: 開発用分割 (dev) で k を選ぶ。候補は k ∈ {1, 3, 5, 7, 9, 13}。基準は事前に固定: 「効果が k=13 の効果の 80% 以上に達する最小の k」。ただし、窓が有効範囲 (7B で約10層) を覆い切らないこと (k ≤ 有効範囲幅の半分、つまり k ≤ 5 を優先)。
- 副解析: k=9 (論文の値、Geva et al. 2023 に倣ったもの) を、論文との比較のためにだけ使う。
- 感度分析: 結論 (有効な層の範囲、経路の順位) が k=5/9/13 で変わらないことを、test でも報告する。

### 妥当性の検討
- k=9 は 32 層の約 28% で、効果のある範囲 (層 6-15 付近、約10層) とほぼ同じ幅になる。窓幅が範囲を覆うので、層ごとの分解能がなく、窓が端にはみ出す層 (1-5) でも効果が出る (予備観察 (a): k=13 で層 1-5 が -10.5%)。層の位置を議論するには広すぎる。
- k=1 は迂回される (予備観察 (a): ほぼ 0)。細すぎる。
- 論文は k=9 を先行研究に倣っただけで、この課題・モデルでの根拠を示していない。
- したがって、k は「効果の大きさ」と「層の分解能」のトレードオフで、データから決める。5 層前後が妥当と予想するが、これは仮説で、dev で確認する (k=3,5,7 は未実行)。
- ヘッド単位の遮断では、窓は層の窓とヘッドの部分集合を掛け合わせる。1ヘッドだけの遮断は、他のヘッドに迂回されて効果が出ない可能性が高い。ヘッド群を単位にする。

## 3. 選抜バイアスの除去 (全実験に共通)
1. 全問を解析対象にする。エンドポイントは、遮断前後の (正解の対数確率 - 最良の誤答の対数確率) の差 (nat)。連続値で、飽和しない。「答えが変わる割合」は副次。
2. 対照 (null) 遮断を、同じ手順で併走する: (i) 同じ本数のランダムな注意の遮断、(ii) k=1 の遮断、(iii) 有効範囲外の層 (層 25 以降)。報告するのは「遮断 − null」の差。
3. 部分集合が必要な場合 (正解のみ) は、正解の判定を、選択肢の並びを入れ替えた別の実行で行い、測定する実行とは独立にする。これで、測定の誤差と選抜の相関を切る。
4. 陽性対照 (必ず効く遮断: 動画→質問の層 6-20 の全遮断) と、陰性対照 (後半層のフレーム間遮断) を事前に指定する。陽性対照が効かなければ、その実験の null は「情報なし」と報告する。
5. 単位は動画。区間は動画単位のブートストラップ。一次解析は1つ。中間の確認 (interim look) はしない。

## 3b. 有効経路の特定基準 (ヘッド探索より先に確定する。「上位3層」のような件数指定は使わない)
対象の経路: フレーム間 / 動画→質問 / 質問→末尾 (それぞれ別に特定)。
1. dev 上で、窓幅 k (2 節で選んだもの) の窓を1層ずつずらして遮断し、層 l ごとに、エンドポイント (nat の margin の変化) の「遮断 − null」を出す。null は 3 節の対照 (ランダムな同数の注意エッジの遮断、後半層の遮断)。
2. 層 l を「有効」とする基準 (結果を見る前に固定):
   (a) 動画単位のブートストラップ 95% 区間の上端が、-δ_min を下回る (δ_min は 4 節の3通りの導出で、dev から決める)。
   (b) 全層 (経路ごと約30層) にわたる多重性を、Benjamini-Hochberg (FDR 5%) で補正する。
   (c) 有効な層が連続する区間を、有効経路の範囲とする。孤立した1層は、範囲に含めず、別に報告する。
3. 範囲の端の安定性を、窓幅 k=3/5/9 で確認 (端が k で動く場合は、その幅を報告し、範囲を1つに決めない)。
4. 範囲の妥当性の確認 (test): その範囲のみ残して他を遮断した場合の精度 (十分性) と、範囲を遮断した場合 (必要性) を、null と比較。
5. この範囲を、ヘッド探索 (5 節) の探索空間とする。範囲外のヘッドは探索しない。

## 4. 有効経路の転用性 (一次解析)
- データ: TVBench 5 タスク (1322 問)。動画単位で dev / test に半分ずつ分割 (乱数 seed 固定)。
- 手順: dev (または、1つのタスクの dev) で、層と k を決め、有効経路 (残す層・接続) を作る。test で評価する。
- 転用の行列: 「選んだタスク」×「評価するタスク」(5×5)。対角 (同じタスク) が上限。非対角が転用性。
- 一次解析 (事前に1つ固定): 「Action Antonym の dev で決めた有効経路を、他の 4 タスクの test に適用したとき、全注意に対する精度差 (nat ベースの margin 差) が、許容幅 δ 以内」を TOST で検定する (非劣性)。
- δ の決め方 (データから、規約ではなく。AGENTS.md の 5 節に従う): (a) 決定の境界付近 (±δ) に入る問題の割合、(b) 標準化した最小の関心効果 (d_z = 0.2 × 動画ごとの差の SD)、(c) 測定のノイズの床 (null 遮断の SD)。3 つを dev で出し、保守的な値を採用。
- 検出力: 動画数 N を、選抜の前に、検出力計算で固定する。論文の枝刈りの差 (-0.3pt) は、δ との関係でのみ議論する。
- 副次: ランダムな遮断 (同じ接続の割合) との差。別モデルへの転用 (13B または他系統、層は相対位置で対応づける) は、交差確認として。

## 5. ヘッド単位の有効経路 (探索的)
目的: 有効層の範囲 (3b 節で決めたもの) の内側で、効果を担うヘッドの集合を特定し、層単位の経路をヘッド単位に細分できるかを見る。
前提: 既存の scripts/run_llava_head_experiment.py (ヘッドごとの加算マスク、eager attention) を再利用する。1回のマスク付き forward は約4秒 (測定済みの前回値、今回は再測定する)。
過去の手法 (層ごとの全ヘッド遮断→上位3層→1ヘッドずつ遮断→上位14ヘッド) は、次の理由で踏襲しない:
 - 「上位3層」「上位14ヘッド」は件数の指定で、効果の有無の基準ではない。
 - 1ヘッドずつの遮断は、他のヘッドに迂回されて効果が出ない (窓幅1が効かないのと同じ構造) ため、組み合わせで効くヘッドを見落とす。加算的でない効果 (相互作用) を捉えられない。
新しい手順:
### 5.1 ランダムな部分集合による主効果のスクリーニング
- 探索空間 P: 3b 節の有効範囲内の全ヘッド (層数×32)。
- P からランダムな部分集合 S (各ヘッドを確率 p で含める。p は dev で、効果が飽和も消失もしない値を探す) を多数引き、S を遮断して、エンドポイント y_S (nat) を測る。
- 回帰: y_S = β0 + Σ β_h x_h (x_h = ヘッド h が S に入るか)。スパース推定 (lasso)。
- 選抜の基準は件数ではなく、安定性選択: 動画のブートストラップで、ヘッド h が選ばれる割合が事前の閾値 (例 80%) 以上で、かつ β_h の符号が一貫していること。
### 5.2 相互作用 (2つ・3つ以上)
- 主効果が選ばれたヘッドの候補プール (強い遺伝性: 主効果の候補どうしの間だけ) で、2次の項 γ_hh'、3次の項 τ_hh'h'' を加えたモデルと比較する。
- 項を残す基準: 保持した部分集合 (held-out の S) での交差検証の予測精度が、加算モデルより事前の幅以上に改善すること。改善しなければ、その次数は採用しない。
- 全ての3つ組を探すと爆発する (候補プールが m ヘッドなら m^3/6 通り) ので、候補プールの大きさ m の上限を事前に固定する (例 40 ヘッド: 約 9,800 組)。
### 5.3 最小集合の特定
- 基準: 有効範囲の全ヘッドを遮断したときの効果の 80% 以上を保つ、最小のヘッド集合 (前向き選択、後ろ向き削除の両方を行い、一致を確認)。
### 5.4 test での検証
- 選んだ集合 vs 同数・同層のランダムなヘッドの遮断 (null 付き)。陽性対照: 有効範囲の全ヘッド遮断。
- 十分性: 選んだヘッドの経路だけを残して他を遮断した精度を、ランダムな同数のヘッドを残した場合と比べる。
- 別タスクでの転用 (4 節の行列のヘッド版)。選抜と同じタスクの test は、転用と区別して報告する。
### 5.5 コストと上限
- 1回の評価の費用: (部分集合数) × (dev 動画数) × 約4秒。例: 200 部分集合 × 30 動画 = 6,000 forward ≈ 6.7 時間 (推定、未測定)。スモークで1 forward の時間を測り、上限を決めてから固定する。
- 連続的なゲート最適化 (L0/L1 付きのヘッドゲート学習) も、組み合わせを自動で扱える代替案だが、7B のバックワードのメモリ (16GB) を、先にスモークで確認する。通らなければ使わない。
### 5.6 失敗時の扱い
- 事前確率が低い探索的な部分。基準を満たすヘッドが出なければ、「寄与が分散している」という結果として報告する。

## 7. 限界・注意
- この計画で測るのは、答えの確率の「遮断への依存」で、説明の忠実さそのものではない。
- TVBench は、答えが動画の端にあるタスクがある (Action Sequence は全問が first、Object Count は begins/ends を問う)。層×時間の操作 (フレーム範囲の遮断) は、本計画では次の拡張とし、本体には含めない。
- 7B の Moving Direction は、偶然水準 (25%) になる可能性があり、そのタスクの結果は解釈できない場合がある。先に、dev でベースライン精度を確認し、偶然水準なら、解析から外す (事前に決めたルールとして)。
- Wilson 区間などの記述は「区間」であって、検定ではない。論文の値との一致は、「矛盾しない」までしか言わない。
- ライセンス: TVBench、NTU RGB+D、TOMATO は、ローカルのみ。再配布しない。
