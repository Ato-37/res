## Interpretation and limits

For these three previously used generated claims, applying this global visual
key bias made the original-versus-time-reversed likelihood contrast lower in
all three rows. This is contrary to the narrow hypothesis that the tested bias
would increase temporal-order sensitivity for these claims. The finite cohort
is tiny and selected; there is no confidence interval, hypothesis test, or
population claim. Reversing temporal blocks changes event order but preserves
the sampled frames, and may create an implausible video. The global bias is not
claim-specific. The claims were generated by the same model and no semantic
claim-support review was performed. Accordingly, this cannot show that the
claims are false, that explanations became less faithful, or that internal
intervention generally harms faithfulness. Dataset and model rights remain
unverified; inputs and detailed receipts remain local.

## Prompt-binding defect and corrected rerun (2026-10-21)

An audit found that the first four-condition run on this `v2_short` packet
imported the legacy `PROMPT_SUFFIX`, which is the `v1` suffix, instead of
resolving the generation prompt version stored on each row. The result above
(`−0.027599` mean, 3/3 negative) is therefore not a valid `v2_short`
measurement and is superseded for this cohort. Its original receipts remain
unchanged as evidence of the defect; they are not silently rewritten.

The scorer now resolves `PROMPT_SUFFIX_BY_VERSION[record.generation_prompt_version]`
once and uses that same suffix for natural and reversed-frame branches. Each
new receipt records the prompt version and suffix hash, and includes a hash of
the resolver source. Focused CPU tests passed **12/12**; the change was also
reviewed independently before GPU scoring. The exact same frozen 3-row packet,
video digests, and claim-text digests were rescored under `v2_short`; this is a
post-hoc measurement repair, not a fresh or confirmatory cohort.
