# NExT-GQA 人手レビュー手順（日本語要約）

この文書は、英語版の[正式手順](nextgqa_v6_human_review_runbook.md)を実施者向けに説明したものです。署名・監査の判定は正式手順と実装に従います。動画・レビュー記録・派生データはローカルに置き、公開しません。権利状態は未確認です。

手軽な予備チェックは[日本語ランチャー](nextgqa_human_review_workspace_ja.html)から開けます。各人がニックネームを入力して「質問へ」を押すと、埋め込み動画つきの質問が表示されます。各項目で、①質問がわかりやすいか、②説明が質問への答えとして合っているか、③説明が動画中の出来事を根拠として示しているか、を別々に選びます。回答後、次の人は「次の人へ」を押し、自分のニックネームを入力してから質問に進みます。最後に「全員分を保存」を押すと、schema v5のJSON一つにまとめて保存します。動画ファイルや時刻を選ぶ必要はありません。Ubuntuターミナルでリポジトリのルートに移動してから、Windowsの既定ブラウザーで開くには次を実行します。

```bash
powershell.exe -NoProfile -Command "Start-Process -FilePath '$(wslpath -w ./data/private_nextgqa/quick_review_ja_simple_20261019_itemid_v10.html)'"
```

Linuxデスクトップ環境で実行する場合は `xdg-open ./data/private_nextgqa/quick_review_ja_simple_20261019_itemid_v10.html` でも開けます。

この簡易artifactは、完全な幻覚判定や正式な人手監査ではありません。ニックネームを入力すると質問に進み、動画ファイル選択や時刻入力なしで大まかな印象を回答できます。署名・担当者の本人性・独立性・動画とdecoder画像の一致・時計校正を確認せず、回答を正式レビュー記録や採点許可として扱いません。簡易artifactは正式レビュー候補と同じ3件を含むため、ここで動画を見た人は同じ項目の盲検正式レビュー担当にはなれません。ニックネーム・回答JSONには個人情報が含まれ得るため、実名を避け、JSONはローカルに保管してください。

担当者ごとに3件へ回答します。二人目以降も各人のニックネームを入力します。全員の回答が済んだら「全員分を保存」を一度押し、まとめたJSONをブラウザのダウンロード先へ保存します。画面のボタンだけではディスクへの保存完了を確認できないため、ブラウザのダウンロード一覧にファイルがあることを確認してください。見当たらない場合は画面に残る「JSONをもう一度ダウンロード」リンクを押せます。回答は最終保存まで開いているタブ内だけに保持され、タブを閉じたり再読み込みしたりすると失われます。ニックネームを含むため、ダウンロード直後のファイルを通常の場所に残したままにせず、リポジトリのルートから次のコマンドで検査してprivate領域へ取り込みます。保存先directoryはmode `0700`、回答JSONはmode `0600` で作成し、既存ファイルは上書きしません。元のダウンロードは自動削除されません。

```bash
.venv/bin/python scripts/import_private_quick_review_response.py \
  /path/to/exploratory_video_review_TIMESTAMP.json
```

既定の出力は形式確認件数と三軸それぞれの集計、private保存先です。ニックネームや個人ごとの回答は表示しません。項目別の選択も確認する場合に限り、コマンド末尾へ `--show-items` を付けてください。privateコピーを確認した後、ダウンロード元が不要ならそのファイルを手動削除してください。これは参加者がその場で選んだ簡単な印象の記述で、正しさ・幻覚性・faithfulnessの推定ではありません。生JSONは公開・commitせず、必要な集計だけを扱ってください。

以下の説明レビュー、時計/画像対確認、予測リンク判定は正式な人手監査の計画です。独立したroot・担当者・署名・引渡し確認を満たすまでは、正式レビューpackageを開封しません。artifact内の簡易な印象回答を、これらの判定に代用しません。

正式監査用の判定入力・署名照合・引渡しの工程は、簡易チェックとは別です。署名や担当者の本人性、開封順序、元動画とフレーム画像の一致、時計校正をartifactの表示だけで合格扱いにせず、必要な証跡を個別に確認します。

## 何を確認するか

対象は候補3件です。モデルが生成した説明文が動画の証拠に支えられるかを人が確認し、説明が指す区間と予測との関係を別段階で判定します。NExT-GQAの質問区間は説明文の証拠区間と同じものではないため、人手で確認した区間の代用にはしません。

1. **第1段階・説明の動画支持（3件）**：担当者は動画全体を通常速度で確認し、説明文全体が見える映像で支持されるかを判定します。支持される場合は、説明を支持する十分な出現区間をすべて記録し、理由を残します。画面に焼き込まれた字幕・文字だけは証拠にしません。
2. **プレイヤー時刻とデコード時刻の照合（15箇所）**：撮影担当者が3動画それぞれの冒頭・中間・末尾を含む指定箇所を実際のレビュー画面で開き、プレイヤー時刻と対応フレームの証跡を保存します。別の担当者が、画面キャプチャとデコード画像の対応を全15組確認します。ここで時刻の原点やずれを測り、区間をモデルの32フレーム入力へ対応付けられるか判定します。
3. **第2段階・予測リンク（3件）**：第1段階とは別の担当者が、固定済みのモデル予測 `p` と対照回答 `q` を見て、レビュー済み区間が `p` を `q` より支持するかを判定します。この判断は介入前に確定します。
4. **内部介入実験**：前段階が通った後に限り、レビュー済み区間に対応する視覚内部表現への介入と、同予算の対照区間・sham条件を比較します。主指標候補は固定した `p` 対 `q` のlog-probability差の変化です。これが示すのは、指定した介入下での予測依存です。説明の真実性やモデル内部の全推論過程を証明するものではありません。

## 開封前に必要な担当と信頼確認

次の役割を実在の担当者に割り当てます。公開鍵は署名確認用で、秘密鍵は共有しません。

| 役割 | 主な仕事 | 独立性 |
|---|---|---|
| 凍結担当（freeze owner） | 対象ファイル・手順を事前に固定し、review-only記録へ署名 | 生成、採点、レビュー、撮影から独立 |
| 保管担当（custodian） | 固定済み素材と記録を保管 | レビュー担当・撮影担当を兼ねない。凍結担当との兼務は可 |
| 撮影担当（capture operator） | レビュー画面と時刻・フレーム対応を記録 | 他の役割から独立 |
| 第1段階レビュー担当 | 説明の支持と区間を判定 | 生成、採点、保管、撮影から独立 |
| フレーム対レビュー担当 | 15組の画面・デコード画像の対応を確認 | 撮影、保管、採点から独立 |
| 第2段階レビュー担当 | 固定済み予測と対照への区間の関連を判定 | 第1段階、生成、採点、保管、凍結、立会いから独立 |
| 独立立会人（release witness） | 開封前の状態と保管引渡しを実際に確認 | 全役割と別人・別鍵 |

さらに、別経路で真正性を確認したroot公開鍵とそのfingerprintが必要です。レビュー担当者の名前・鍵をレビュー素材自身から信頼してはいけません。役割、公開鍵、root fingerprintを[日本語の役割割当票](nextgqa_human_review_role_assignment_template_ja.md)へ記入します。個人連絡先や秘密鍵は記載しません。

## 実施順序

1. 担当者と鍵を割り当て、root fingerprintを別経路で確認する。
2. 凍結担当が対象データ、レビュー画面、方針、32フレームsampler、実装などの正確なファイルを選び、inventoryでhash固定する。レビュー結果やモデル出力を見てから対象・閾値・samplerを変えない。
3. 信頼済みrootが役割名簿へ署名し、凍結担当は実験実行を認めない `review_only` receiptへ署名する。
4. 立会人が未開封の素材と署名を確認し、凍結担当から保管担当への引渡しを見届ける。
5. `scripts/audit_nextgqa_review_release_order.py` が、root、名簿、receipt、inventory、立会い記録の全てを検証し、`package_opening_permitted=true` となった後に限り、オフラインでレビュー資料を開く。失敗したら開かず、原因を直して固定・引渡しをやり直す。
6. 第1段階レビュー、撮影証跡、独立した15組のフレーム確認を行い、それぞれ署名・構造監査する。
7. 予測 `p/q` を固定してから、第2段階レビューを別担当者が行う。その後、スコア用の全入力・条件・解析手順を再度hash固定する。
8. 専用のスコア前監査が通るまでモデルの採点・介入を始めない。現在、運用可能な最終スコアfreezeは未成立です。

## 現在の進捗と次に必要なもの

現状は**説明レビュー0/3、時刻・フレーム照合0/15、第2段階判定0/3、直接採点0/3**です。役割割当の空欄に加えて、独立確認済みroot fingerprint、署名済み名簿、review-only receipt、立会人が確認した未開封引渡しがありません。したがってレビュー資料をまだ開きません。これは人手レビューの手順・真正性を守るための工程で、GPU実験や合成データでの準備作業は並行できます。

レビューの完了は「faithfulnessが高い」という結論ではありません。人の確認した区間への予測依存と、選んだ介入条件での効果を測るための入力が揃ったことを意味します。小標本の3件から一般的な効果や因果的な説明忠実性へ広げて主張することもできません。
